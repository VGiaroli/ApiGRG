# ApiGRG Admin 2.0 Implementation Plan

> **For agentic workers:** Implement this plan task-by-task on branch `Matias`. Do not create or execute tests, builds, linters, browser checks, manual validations, or database migrations.

**Goal:** Implement the five Admin 2.0 phases while preserving the public catalog contract and leaving the API without new `[Authorize]` attributes.

**Architecture:** Extend the existing EF Core model with nullable inventory fields, a stock movement aggregate, and optimistic concurrency. Keep `GET /api/productos` public and compatible, add explicit administrative projections and partial product operations, and expose a real dashboard summary. Refactor the dynamic sidebar into an idempotent shared component and reuse catalog presentation rules in an administrative preview module.

**Tech Stack:** ASP.NET Core 8, Entity Framework Core 8 with SQL Server, HTML/CSS/vanilla JavaScript, Bootstrap 5, Bootstrap Icons, SweetAlert2, existing JWT helper.

**Assumptions:**
- Existing products keep `StockActual = null`; this excludes treating missing stock as zero.
- `Disponible` remains the stored commercial flag; public `disponible` is effective availability; this excludes publishing SKU or internal movements.
- The API remains open in this iteration; this excludes adding `[Authorize]` while preserving existing frontend session behavior.
- Stock is per product and colors remain descriptive variants; this excludes warehouses, reservations, and per-color quantities.
- The user forbids test/build/lint/runtime validation; this excludes creating test files or running verification commands.
